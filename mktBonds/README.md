# Published market Treasury reports

Reference for the files produced by [job-mktBonds-update.sh](./job-mktBonds-update.sh)
and [job-mktTips-update.sh](./job-mktTips-update.sh). For calculation-library details
and historical REFCPI configuration, see [lib/README.md](./lib/README.md).

## REFCPI in Google Sheets

The toolkit custom function in
[tips.cloudFlare.REFCPI.js](./toolkit-app-script-src/tips.cloudFlare.REFCPI.js)
can be used as `=tipsGetCachedREFCPI()` to spill a table into a worksheet.
It includes the header row `Date`, `REFCPINSA`, `REFCPISA`, `SAFactor`, `MMDD`,
`maxREFCPI`. The first and last columns contain date values; format those
columns as dates in Sheets. CPI values and seasonal factors are numeric.
Leave the six-column output area empty so the array can expand.
Use `=tipsGetCachedREFCPI(TRUE)` to bypass (and refresh) the cache.
Fresh and cached toolkit rows both retain date values. CSV input may use LF
or CRLF line endings, with or without a trailing newline; the final retained
row is included in both exact-date and seasonal-factor projection lookups.

Use `=tipsGetMaxRefCpiDate()` from
[tips.utils.js](./toolkit-app-script-src/tips.utils.js) to return the maximum
REFCPI date as `YYYY-MM-DD` text, without a time or timezone.

The underlying `cloudGetCachedREFCPI` continues returning row objects for the toolkit's calculation helpers.

## Locations and file types

The publication directory is `$cloudFlareHome/Treasuries/mktBonds`, typically
`~/cloudflare/public/Treasuries/mktBonds`.

Public report location:
[cashoptimizer.pages.dev/Treasuries/mktBonds/](https://cashoptimizer.pages.dev/Treasuries/mktBonds/).

| Location / extension | Contents |
|---|---|
| `<name>-rate.csv` | Latest published tabular report, with a header row. |
| `<name>-rate.json` | Latest published data and, for fitted curves/grids, model metadata. |
| `daily/*.csv`, `daily/*.json` | Timestamped snapshots of changed published reports; naming rules below. |
| `mktTips-manifest.txt` | Sorted CSV basenames matching `mktTips-*.csv` in the publication directory. |
| `mktNominal-manifest.txt` | Sorted CSV basenames matching `mktNominal-*.csv` in the publication directory. |
| `mktBei-manifest.txt` | Sorted CSV basenames matching `mktBei-*.csv` in the publication directory. |
| `daily/mktTips-manifest.txt`, `daily/mktNominal-manifest.txt`, `daily/mktBei-manifest.txt` | Sorted timestamp-prefixed CSV basenames for the corresponding archive family. |

Manifests contain one filename per line, not CSV rows, and are regenerated by the
TIPS publication job. They list matching files actually present, including any
older files that have not been migrated or removed. There is no combined
`mktBonds` manifest from these jobs.

Local `history/<name>-rate-new.json` files are working outputs, not public
archives. Temporary collection/publication files are not report types. The
shared publisher's per-CUSIP history branch is disabled; these jobs do not
currently publish per-CUSIP history files.

### Naming conventions

- `mkt`: market-price input.
- `Nominal`: nominal Treasuries; `Tips`: inflation-indexed Treasury securities;
  `Bei`: break-even inflation (nominal minus TIPS).
- `curve`: maturity-based bond diagnostics, with one row per included CUSIP.
  These CSVs report bond YTMs, not zero rates sampled at those maturities.
- `grid`: fitted zero rates and discount factors at standard tenor points.
- No `fwd`: settlement-date valuation; `fwd`: valuation at the forward date.
  A forward-based zero curve is not a table of interval forward interest rates.
- `sa`: seasonally adjusted input prices.
- `sa-decay`: seasonal adjustment with the maturity factor decayed toward 1
  using the credibility calculation.
- `ask` / `bid`: selected quote side, used consistently for the TIPS input,
  financing-rate derivation, and corresponding nominal fit.
- `rate`: historical publication suffix; it does not imply every column is a rate.

#### Archive filenames

The prefix is the report's `asOfDate`, for example `2026-10-08T1405`, not the
time at which the publishing job runs.

| Latest file | Corresponding file under `daily/` |
|---|---|
| `mktBonds-rate.<ext>` | `<asOfDate>-rate.<ext>` |
| `mktNominal-<side>-rate.<ext>` | `<asOfDate>-mktNominal-<side>.<ext>` |
| `mktTips-<side>-rate.<ext>` | `<asOfDate>-mktTips-<side>.<ext>` |
| `mktTips-curve-<qualifiers>-rate.<ext>` | `<asOfDate>-mktTips-curve-<qualifiers>.<ext>` |
| `mktNominal-grid-<qualifiers>-rate.<ext>` | `<asOfDate>-mktNominal-grid-<qualifiers>.<ext>` |
| `mktBei-grid-<qualifiers>-rate.<ext>` | `<asOfDate>-mktBei-grid-<qualifiers>.<ext>` |

`<ext>` is `csv` or `json`. Snapshots are written when the publisher detects
changed JSON; repeated publication with the same timestamp uses the same archive
filename.

The `mktTips-fitHistory` and `mktBei-stability` reports are rebuilt from the
whole archive on each run and are not themselves archived under `daily/`.

Older nominal grid reports were named `mktNominal-curve-*`. To migrate those
filenames and their nominal manifest entries, use
[rename-mktNominal-archive.sh](./rename-mktNominal-archive.sh):

```bash
# Preview first; this can target the publication directory or its parent.
bash mktBonds/rename-mktNominal-archive.sh ~/cloudflare/public/Treasuries/mktBonds
# Apply while publication jobs are stopped; back up the archive beforehand.
bash mktBonds/rename-mktNominal-archive.sh --apply ~/cloudflare/public/Treasuries/mktBonds
```

The migration preserves `mktTips-curve-*` filenames.

## Units, dates, and interpretation

- Rates, coupons, and inflation spreads are annual decimals: `0.04` means 4%.
  One basis point is `0.0001`. `residualBp` is already in basis points.
- Prices and price residuals are per $100 par. TIPS clean prices are quoted
  real prices, not inflation-indexed cash settlement amounts. Clean prices
  exclude accrued interest.
- REFCPI values are index levels. Seasonal ratios and discount factors are
  dimensionless.
- `asOfDate` is the source download timestamp in New York market time, formatted
  `YYYY-MM-DDTHHmm` without a timezone suffix. The collector converts the source's
  Pacific download time to New York time.
- Calendar-date columns use `YYYY-MM-DD`. Settlement is the next bond-market
  business day after the quote date, using SIFMA holidays when available. If the
  holiday lookup fails, the processor warns and skips weekends only.
- The forward date is the last available REFCPI date (`maxREFCPI` horizon), not
  a fixed tenor. Historical `--asOfDate` configuration can cap this horizon; it
  does not itself retrieve historical quotes.
- YTMs use the Treasury coupon-equivalent yield calculation with semiannual
  coupons. Zero-coupon securities under six months use the Treasury
  investment-rate formula. TIPS YTMs are real yields.
- Null JSON values become empty CSV fields. Blank quote fields mean unavailable
  data, not zero. A blank `richCheap` has a separate meaning: a residual below
  the classification threshold.
- Calculated rates/yields and seasonal ratios generally use five decimal places,
  clean prices six, grid discount factors six, and `residualBp` three.
  Displayed precision does not imply equivalent model accuracy.

## CSV column glossary

Columns below are listed in their published order. Shared columns are defined
once and referenced by the family-specific sections.

### Combined quotes: `mktBonds-rate.csv`

| Column | Definition |
|---|---|
| `asOfDate` | Source quote-download timestamp; see date conventions above. |
| `cusip` | Security identifier. Treat as text, preserving leading zeros. |
| `securitytype` | Collector classification: `Bond` (including notes), `Bill`, `TIPS`, or `STRIP`. |
| `interest_rate` | Annual coupon as a decimal; blank when absent in the source. Not a yield. |
| `maturity_date` | Security's final maturity date. |
| `bid` | Quoted bid clean price per $100. |
| `ask` | Quoted ask clean price per $100. |
| `description` | Security description from the quote source. |

### Nominal bond table: `mktNominal-<side>-rate.csv`

Contains quoted nominal `Bond` and `Bill` securities maturing after settlement.
STRIPS and TIPS are excluded. A security can appear here even if it is later
excluded from the nominal zero-curve fit.

| Column | Definition |
|---|---|
| `cusip` | Security identifier. |
| `interest_rate` | Annual nominal coupon as a decimal. Bills have a zero coupon. |
| `security_type` | `Bond` (including notes) or `Bill`; note the spelling differs from the combined feed. |
| `description` | Source description. |
| `maturity_date` | Final maturity date. |
| `report_source` | Source and selected side, currently `Market ask` or `Market bid`. |
| `asOfDate` | Source quote-download timestamp. |
| `settle_date` | Settlement valuation date. |
| `fwd_date` | Forward valuation date at the REFCPI horizon. |
| `settle_clean_price` | Selected-side quoted clean price at settlement. |
| `repo_rate` | Annual simple financing rate used to carry prices forward. By default derived from selected-side T-bills bracketing the forward date; can be supplied explicitly. |
| `fwd_clean_price` | Repo-carried forward clean price, allowing for intervening coupon cash flows and forward accrued interest. Null when maturity is before the forward date. |
| `settle_ytm` | YTM from `settle_clean_price` at `settle_date`. |
| `forward_ytm` | YTM from `fwd_clean_price` at `fwd_date`; null when forward yield cannot be calculated, including maturity on/before that date. |

### TIPS bond table: `mktTips-<side>-rate.csv`

Joins Treasury TIPS metadata to the selected quote side. Includes quoted TIPS
maturing after settlement, even if they will mature before the forward date.

| Column | Definition |
|---|---|
| `cusip` | Security identifier. |
| `interest_rate` | Annual real coupon as a decimal. |
| `security_term` | Original issue term in years from Treasury metadata, not remaining time to maturity. |
| `series` | Treasury issue-series label from metadata. |
| `maturity_date` | Final maturity date. |
| `dated_date` | Security's dated date, used for its base reference CPI. |
| `report_source` | `Market ask` or `Market bid`. |
| `asOfDate` | Source quote-download timestamp. |
| `settle_date` | Settlement valuation date. |
| `fwd_date` | Forward valuation date at the REFCPI horizon. |
| `settle_clean_price` | Selected-side quoted real clean price at settlement. |
| `dated_refcpi` | Reference CPI on the security's dated date; denominator for its inflation index ratio. |
| `settle_refcpi` | Reference CPI at settlement. |
| `fwd_refcpi` | Reference CPI at the forward date. |
| `settle_mature_sa_ratio` | Settlement seasonal factor divided by the maturity seasonal factor; multiply settlement clean price by this ratio for SA pricing. |
| `settle_mature_sa_ratio_decay` | Same ratio with the maturity factor credibility-decayed toward 1 over the settlement-to-maturity horizon. Published maturity factors remain exact. |
| `fwd_mature_sa_ratio` | Forward-date seasonal factor divided by the maturity seasonal factor; multiply forward clean price by this ratio for SA pricing. |
| `fwd_mature_sa_ratio_decay` | Same ratio with maturity-factor credibility decay measured from the forward date. Published maturity factors remain exact. |
| `repo_rate` | Annual simple financing rate; derived from selected-side T-bills by default. |
| `fwd_clean_price` | Forward quoted real clean price from financing the indexed dirty value, accounting for coupon cash flows, forward CPI indexing, and accrued interest. Null when maturity is before the forward date. |
| `settle_ytm` | Real YTM from unadjusted settlement clean price. |
| `settle_sa_ytm` | Real YTM from `settle_clean_price * settle_mature_sa_ratio`. |
| `settle_sa_decay_ytm` | Real YTM from `settle_clean_price * settle_mature_sa_ratio_decay`. |
| `forward_ytm` | Real YTM from unadjusted forward clean price at `fwd_date`. |
| `forward_sa_ytm` | Real YTM from `fwd_clean_price * fwd_mature_sa_ratio`. |
| `forward_sa_decay_ytm` | Real YTM from `fwd_clean_price * fwd_mature_sa_ratio_decay`. |
| `settle_sao` | SAO yield fit/blend of settlement SA-decay YTMs, without the short-end clamp. |
| `forward_sao` | SAO yield fit/blend of forward SA-decay YTMs, without the short-end clamp. |
| `settle_sao_tweak` | Settlement SAO with the fitted curve held flat below its shortest fitted maturity. |
| `forward_sao_tweak` | Forward SAO with the same short-end clamp. |

SAO fits the input YTMs directly with a Nelson-Siegel-Svensson yield function; it
is not the cash-flow-priced zero-curve model used in the `mktTips-curve-*`
reports. Maturities below 0.5 years are excluded from its fit. Outputs use the
fit through five years, blend linearly back to input yields between five and
six years, and retain input yields at/after six years. Without a usable fit,
SAO retains raw input yields. Blank inputs remain null.

The SAO columns support comparison with the yield-curve approach used by
aerokam's [Treasury Investors Portal](https://aerokam.github.io/Treasuries/YieldCurves/).
This project adapts aerokam's published SAO algorithms to its own data pipeline
and adds settlement/forward comparisons and optional short-end clamping. Shared
algorithm ancestry does not imply identical results.

The seasonal-factor credibility-decay calculation is also adapted from aerokam's
published implementation in
[ref-cpi.js](https://github.com/aerokam/Treasuries/blob/main/shared/src/ref-cpi.js).
It reduces the projected maturity seasonal factor's departure from 1 as the
projection horizon increases.

### TIPS maturity-curve diagnostics: `mktTips-curve-*-rate.csv`

All six variants use the same columns. Both settlement and forward fits exclude
TIPS maturing on/before the forward date. Adjusted fits also exclude rows missing
their required seasonal ratio.

| Filename qualifier | Valuation date | Input clean price | Published basis suffix |
|---|---|---|---|
| none | Settlement | `settle_clean_price` | `settle` |
| `sa` | Settlement | `settle_clean_price * settle_mature_sa_ratio` | `settle-sa` |
| `sa-decay` | Settlement | `settle_clean_price * settle_mature_sa_ratio_decay` | `settle-sa-decay` |
| `fwd` | Forward | `fwd_clean_price` | `forward` |
| `fwd-sa` | Forward | `fwd_clean_price * fwd_mature_sa_ratio` | `forward-sa` |
| `fwd-sa-decay` | Forward | `fwd_clean_price * fwd_mature_sa_ratio_decay` | `forward-sa-decay` |

| Column | Definition |
|---|---|
| `cusip` | Actual TIPS security whose cash flows are being evaluated. |
| `asOfDate` | Source quote-download timestamp shared by the TIPS and nominal inputs. |
| `basis` | Source, side, and valuation/adjustment basis, e.g. `Market-ask-forward-sa`. |
| `settleDate` | Model valuation date. Despite its name, this is the forward date in forward-based reports. |
| `maturity` | Actual TIPS maturity date. |
| `coupon` | Annual real coupon as a decimal. |
| `marketClean` | Input clean price for this basis, including forward carry and/or seasonal adjustment where selected. It is not necessarily the raw market quote. |
| `modelClean` | Curve-implied clean price: discount the bond's coupon and principal cash flows with the fitted real zero curve, then subtract accrued interest. |
| `priceResidual` | `marketClean - modelClean`, per $100; negative means the input price is below model price. Calculated before display rounding. |
| `marketYtm` | Real YTM from the input price at the model valuation date. |
| `modelYtm` | Curve-implied real YTM from the model price at that date; not the zero rate at final maturity. |
| `residualBp` | `(marketYtm - modelYtm) * 10000`, in basis points. |
| `richCheap` | `cheap` for positive yield residuals of at least 2 bp; `rich` for negative residuals of at least 2 bp in magnitude; blank otherwise. Classification uses the published rounded residual. |
| `nominalMarketYtm` | Local linear fit of up to six nearest included nominal bond YTMs, evaluated at the TIPS maturity. Null outside the included nominal maturity range or with fewer than two nominal observations. Not a nominal zero rate or an exact coupon-matched yield. |
| `marketBei` | `nominalMarketYtm - marketYtm`, an annual decimal yield spread; null when the nominal market estimate is unavailable. |
| `nominalModelYtm` | YTM of a hypothetical nominal bond with this TIPS coupon and maturity, priced using the corresponding nominal zero curve at the same valuation date. |
| `modelBei` | `nominalModelYtm - modelYtm`, the coupon/maturity-matched model yield spread as an annual decimal. |
| `nominalResidualBp` | `(nominalMarketYtm - nominalModelYtm) * 10000`, in basis points: how far the local nominal market yield sits from the nominal curve at this maturity. Null when `nominalMarketYtm` is null. |
| `beiResidualBp` | `nominalResidualBp - residualBp`, i.e. `(marketBei - modelBei) * 10000` computed from the published residuals, in basis points. Positive means the bond's market BEI is above the curves' BEI. Separating it from `nominalResidualBp` shows whether a gap comes from the TIPS or the nominal side. Null when `nominalMarketYtm` is null. |
| `zeroBei` | Nominal minus TIPS zero rate at the bond's maturity date, both semiannual (`zeroBey`); the `mktBei-grid-*` `beiBey` value read at this maturity instead of at a grid tenor. |

The nominal comparison uses the matching side's settlement or forward
`mktNominal-grid-*` fit. BEI means break-even inflation here; these spreads can
reflect liquidity, risk premia, and the chosen seasonal adjustment as well as
inflation expectations. They are yield differences, not inflation forecasts or
zero-coupon inflation swap rates.

### Nominal zero-rate grid: `mktNominal-grid-*-rate.csv`

Contains 60 points, from 0.5 to 30 years in six-calendar-month increments from
the valuation date. The fit uses selected-side, non-STRIP nominal notes, bonds,
and bills maturing after the forward date. The fitter filters candidates by
absolute yield deviation, with a default threshold of 15 bp and up to five fit
passes. Exclusion details appear in JSON, not in this CSV.

| Column | Definition |
|---|---|
| `asOfDate` | Source quote-download timestamp. |
| `basis` | Source, side, and valuation basis, e.g. `Market-bid-settle` or `Market-ask-forward`. |
| `curveDate` | Zero-curve valuation date: settlement or forward date. |
| `term` | Nominal grid tenor in years: 0.5, 1, 1.5, ..., 30. |
| `date` | Calendar date reached by adding the grid tenor to `curveDate`, clamped to month end when necessary. |
| `zeroCc` | Annual continuously compounded nominal spot zero rate for this date. |
| `zeroBey` | Same zero rate expressed with semiannual compounding: `2 * (exp(zeroCc / 2) - 1)`, calculated from the unrounded zero rate. |
| `discountFactor` | Present value of $1 paid at `date`: `exp(-zeroCc * t)`, where `t` is actual days from `curveDate` divided by 365; calculated from unrounded values. |

`term` is a calendar-grid label; the model's actual-days/365 year fraction can
differ slightly. Grid rates are genuine zero rates, unlike the coupon-bond
`marketYtm` / `modelYtm` columns in maturity-based reports.

### Break-even inflation grid: `mktBei-grid-*-rate.csv`

Contains the same 60 grid points as the nominal grid. TIPS zero rates are read
off the Svensson real zero curve of the corresponding `mktTips-curve-*` fit
(same qualifiers and quote side); nominal zero rates are read off the
`mktNominal-grid-*` fit for the same side and valuation date (settlement for
unqualified/`sa`/`sa-decay`, forward for `fwd*`). The nominal columns therefore
match the corresponding nominal grid report's `zeroCc` / `zeroBey`.

| Column | Definition |
|---|---|
| `asOfDate` | Source quote-download timestamp shared by both curves. |
| `basis` | TIPS curve basis, e.g. `Market-ask-forward-sa-decay`. |
| `nominalBasis` | Nominal curve basis, e.g. `Market-ask-forward`. |
| `curveDate` | Zero-curve valuation date for both curves: settlement or forward date. |
| `term` | Grid tenor in years: 0.5, 1, 1.5, ..., 30. |
| `date` | `curveDate` plus `term`, clamped to month end when necessary. |
| `tipsZeroCc` | Annual continuously compounded real spot zero rate. |
| `tipsZeroBey` | Real zero rate with semiannual compounding. |
| `nominalZeroCc` | Annual continuously compounded nominal spot zero rate. |
| `nominalZeroBey` | Nominal zero rate with semiannual compounding. |
| `beiCc` | `nominalZeroCc - tipsZeroCc`: zero-coupon break-even spread, continuously compounded. |
| `beiBey` | `nominalZeroBey - tipsZeroBey`: the same spread on a semiannual basis. |

Spreads are calculated from unrounded zero rates, so they can differ in the last
digit from the difference of the displayed columns. The short end of the TIPS
fit is weakly constrained (and seasonally sensitive without `sa`), so early
points should be interpreted with care. The same BEI caveats as above apply.
JSON includes `asOfDate`, `basis`, `nominalBasis`, `settleDate`, `method`,
`tipsParams`, `nominalParams`, and grid `points`.

### Seasonal-adjustment fit history: `mktTips-fitHistory-*`

Built by [node-calc-mktTips-fitHistory.mjs](./node-calc-mktTips-fitHistory.mjs)
from every `daily/<asOfDate>-mktTips-curve-*.json` fit at the end of each TIPS
job run. It answers whether credibility decay (`sa-decay`) fits market prices
better than plain seasonal adjustment (`sa`). "Short" bonds mature within
`shortYears` (default 3) of the curve date.

`mktTips-fitHistory-rate.csv` has one row per snapshot, side, valuation, and
adjustment:

| Column | Definition |
|---|---|
| `asOfDate` | Snapshot timestamp of the archived fit. |
| `side` | `ask` or `bid`. |
| `valuation` | `settle` or `forward`. |
| `adjustment` | `none`, `sa`, or `sa-decay`. |
| `curveDate` | Fit valuation date. |
| `bonds` / `shortBonds` | TIPS in the fit / those maturing within `shortYears`. |
| `objective` | Fitter's price-error objective; lower is better. Compare adjustments only where `bonds` matches (adjusted fits drop TIPS missing a seasonal ratio). |
| `rmsBp`, `shortRmsBp`, `longRmsBp` | Root-mean-square yield residual (`residualBp`) over all, short, and remaining bonds. |
| `maxAbsBp` | Largest absolute yield residual. |
| `monthRangeBp` | Highest minus lowest mean short-bond residual by maturity month: the seasonal pattern the adjustment left in the fit. |
| `zero1y`, `zero2y` | Fitted TIPS continuously compounded zero rate at 1 and 2 years (actual/365). |

`mktTips-fitHistory-summary-rate.csv` has one row per side and valuation,
pairing each snapshot's `sa-decay` fit with its `sa` fit (only when both fit the
same number of bonds):

| Column | Definition |
|---|---|
| `side`, `valuation` | As above. |
| `snapshots` / `days` | Snapshots with both fits / distinct calendar dates among them. |
| `firstAsOfDate`, `lastAsOfDate` | Range covered. |
| `decayWins`, `decayWinShare` | Snapshots where `sa-decay` has the lower objective, as a count and share. |
| `objectiveChangePct` | Mean of `(sa-decay objective / sa objective - 1) * 100`; negative favors decay. |
| `rmsDeltaBp`, `shortRmsDeltaBp`, `longRmsDeltaBp`, `maxAbsDeltaBp`, `monthRangeDeltaBp` | Mean `sa-decay` minus `sa` difference of the per-snapshot statistic; negative favors decay. |
| `zero1yMeanAbsDiffBp`, `zero2yMeanAbsDiffBp` | Mean absolute difference between the two TIPS zero rates at 1 and 2 years, in bp. Both fits share a nominal curve, so this is also the short-end BEI difference the choice makes. |
| `verdict` | `insufficient history` when `days` is below `minDays` (default 10); otherwise `sa-decay better` when decay wins at least two-thirds of snapshots, `sa better` when it wins at most one-third, and `mixed` in between. |

Snapshots taken on the same day are strongly correlated, which is why the
history threshold counts distinct days rather than snapshots.

### Settle against forward BEI stability: `mktBei-stability-*`

Built by [node-calc-mktBei-stability.mjs](./node-calc-mktBei-stability.mjs)
from the `daily/` archive. It asks whether the forward-date BEI is more stable,
less sensitive to individual bonds, and better fitted than the settle-date BEI,
for the `sa` and `sa-decay` curves on each side. Only the last complete snapshot
of each calendar date is used. A snapshot is complete when it has the
`mktTips-<side>` rows, both nominal grids, and the four seasonally adjusted TIPS
curves.

**Like-for-like comparison.** The forward date is meant to remove the inflation
that is already known (published CPI) between settlement and the forward date.
The two BEI rates are related by:

`forwardBei(T) * T = settleBei(gap + T) * (gap + T) - knownInflation`

- `gap` is the time from settlement to the forward date, in years.
- `knownInflation = ln(fwd_refcpi / settle_refcpi) + ln(settle_mature_sa_ratio / fwd_mature_sa_ratio)`.
  The ratio-of-ratios term is the same for every maturity on the `sa` curve, so
  the median across bonds is used. `sa-decay` uses the same value as an
  approximation.
- The repo rate cancels, because the nominal and TIPS forward curves carry at
  the same repo rate.

The archive confirms the identity to within about 0.1 bp at 5 years, 0.3 bp at
2 years, 0.6 bp at 1 year, and 2–3 bp at 6 months. Raw settle BEI looks
steadier only because the fixed known-inflation part dilutes its daily moves.
So the verdicts compare forward BEI against this settle-implied forward BEI,
not against the raw settle BEI.

`mktBei-stability-rate.csv` has one row per date, side, adjustment, and
valuation. The tenors are 0.5, 1, 2, and 5 years; in column names the key
`0_5` means 0.5 years.

| Column | Definition |
|---|---|
| `curveDate` / `forwardDate` | Valuation date of the curve / the TIPS forward date (CPI horizon). |
| `bonds`, `shortBonds` | Bonds in the fit / bonds maturing within `shortYears` (default 3) of the curve date. |
| `shortRmsBp`, `shortPriceRms` | Root mean square of the short bonds' yield residuals (bp) and price residuals (per $100). |
| `knownInflation` | Settle rows only: the log known-inflation term defined above. |
| `nominal{k}y`, `bei{k}y` | Continuously compounded nominal zero rate and BEI (nominal minus TIPS zero) at the tenor, measured from the curve date. |
| `implied{k}y` | Settle rows only: settle-implied forward BEI at the tenor. |
| `loo{k}yBp`, `loo{k}yCusip` | Leave-one-out: the largest move in `bei{k}y` (bp) when each short bond is dropped in turn and the curve is refitted, and the bond that caused it. |
| `looImplied{k}yBp` | The same leave-one-out measure for `implied{k}y`. |

`mktBei-stability-summary-rate.csv` has one row per side, adjustment, and tenor:

| Column | Definition |
|---|---|
| `days`, `changes` | Dates used / day-to-day changes. A change is skipped when the forward date moved between the two dates (a new CPI release shifts the horizon). |
| `settleBei`, `impliedBei`, `forwardBei`, `impliedGapBp` | Means of each BEI, and the mean absolute gap between implied and forward BEI in bp. |
| `settleChangeBp`, `impliedChangeBp`, `forwardChangeBp` | Root mean square of the daily BEI changes, in bp. |
| `settleNominalChangeBp`, `forwardNominalChangeBp` | The same for the nominal zero rate. Comparing these with the BEI changes shows whether BEI moves come from the nominal side or the TIPS side. |
| `settleLooBp`, `impliedLooBp`, `forwardLooBp` | Mean leave-one-out move. |
| `settleShortRmsBp`, `forwardShortRmsBp`, `settleShortPriceRms`, `forwardShortPriceRms` | Mean short-bond fit statistics. |
| `stabler` | Compares `impliedChangeBp` with `forwardChangeBp`. Returns `insufficient history` when `days` is below `minDays` (default 10). |
| `robuster` | Compares `impliedLooBp` with `forwardLooBp`. |
| `fitter` | Compares the short-bond price residuals. Price is used rather than yield because forward bonds have less time to maturity, which inflates their yield residuals. |

Each verdict is `forward`, `settle`, or `similar`. It is `similar` when the two
values are within 10% of each other.

Leave-one-out refits are cached in `history/mktBei-stability-cache.json`, so
each run only refits new dates. The cache is pruned to the dates in use.

## JSON companion files

Quote and bond-table JSON files contain arrays of rows. Nominal bond-table JSON
also retains `bid` and `ask`, which are not included in its selected-side CSV.

Curve/grid JSON files are objects, not arrays:

- TIPS curve JSON includes `asOfDate`, `basis`, `settleDate`, `method`, `params`,
  `objective`, and per-bond `rows`.
- Nominal grid JSON includes `asOfDate`, `basis`, `settleDate` (the curve valuation
  date), `forwardDate`, `priceSide`, `method`, `params`, `objective`, `bondsUsed`,
  `excluded`, `fitBonds`, and grid `points`.

`method` is `Svensson`; `params` are the fitted zero-curve parameters and
`objective` is the fitter's price-error objective. `fitBonds` records the nominal
instruments used and their observed YTMs. `excluded` records omitted nominal
instruments with `cusip`, `maturity`, `coupon`, `ytm`, and signed `deviationBp`
(market minus model yield). These metadata are not additional published CSV
columns.
